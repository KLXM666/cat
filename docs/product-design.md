# 纯文本阅读器 · 产品设计文档

> 版本：v0.1（MVP 定稿）
> 状态：待开发
> 最后更新：2026-10-25

---

## 1. 产品定位

**一句话**：一个只读 `.txt` 的本地网页阅读器，打开快、排版稳、进度不丢。

**不做**：不做书城、不做社交、不做云同步、不做多格式万能阅读器。

**核心主张**：中文长文本（尤其是网络小说）在手机和电脑上的阅读体验长期被"能打开"敷衍，我们要在**排版质量**和**续读可靠性**这两件小事上做到没有硬伤。

---

## 2. 目标场景

| 场景 | 描述 |
|---|---|
| 主力场景 | 手上有一批 `.txt` 小说（几十万字到数百万字），想在浏览器里舒适地读 |
| 次要场景 | 临时打开一份 `.txt` 长文档（说明、稿件、导出文本）只是想看清楚 |
| 明确排除 | 学术阅读（需要批注、引用、双栏）、漫画/图片书、DRM 内容 |

**目标用户**：自己管理文本文件、不在意云同步、只要求"打开就能好好读"的人。

---

## 3. 设计原则

按优先级排序，冲突时上位优先。

1. **打开即读**：从选文件到看见正文，不超过一次点击、一秒钟。
2. **续读不漂移**：改字号、改窗口、换设备尺寸后，仍然回到原位置。
3. **大文件不卡死**：20MB / 800 万字的书，滚动不能掉帧、不能白屏。
4. **零构建**：`index.html` + ES modules，浏览器直接跑，不需要打包器。
5. **数据在本地**：书本与进度只存在本机 IndexedDB，不上传任何东西。
6. **宁缺毋滥**：任何功能先问"去掉它，还能不能好好读书"。能，就去掉。

## 4. 功能范围

### 4.1 MVP 必做

| 模块 | 功能点 |
|---|---|
| 导入 | 选择本地 `.txt` 文件；自动识别 UTF-8 / GB18030 编码；拒绝超限文件并提示 |
| 归一化 | 换行符统一；分段策略自适应；剥离全角缩进；过滤广告行；压缩空行 |
| 章节 | 正则自动识别章节标题，生成章节列表；无标题时按固定字数切块兜底 |
| 书架 | 极简列表：书名 + 首字色块 + 进度百分比；支持删除 |
| 阅读 | 滚动式阅读；只渲染当前章；上一章 / 下一章切换 |
| 导航 | 侧栏章节列表，点击跳转 |
| 进度 | 自动保存 `{章序号, 章内百分比}`；打开时精确恢复 |
| 设置 | 字号、行距、主题（亮 / 暗 / 护眼）；设置项持久化 |
| 快捷键 | `←/→` 切章、`Esc` 关侧栏、`+/-` 调字号 |

### 4.2 明确不做（v0.1 范围外）

- EPUB / MOBI / AZW3 / PDF 等任何其他格式
- 高亮、批注、笔记、书签
- 账号、云同步、多端同步
- 划词词典、TTS 朗读、翻译
- 真实翻页动画（page-turn）
- 在线书源、书城、推荐
- 字体上传、自定义 CSS
- 搜索全书

> 这些不是"永不做"，是"v0.1 不做"。见第 9 节迭代路线。

## 5. 关键设计决策

### 5.1 章节切分是基础设施，不是功能

章节切分同时承担三件事，任一都不可省略：

1. **导航**：几十万字的书没有章节边界，用户无法定位。
2. **进度可靠性**：纯像素 `scrollTop` 会因字号和窗口变化而漂移；`{章序号, 章内百分比}` 不漂移。
3. **渲染性能**：一次性把 800 万字塞进 DOM 会直接卡死标签页，必须按章分片渲染。

因此即使用户"不需要目录"，切分逻辑也必须存在。UI 上表现为侧栏列表。

### 5.2 编码探测优先于一切

国内 `.txt` 大量为 GBK/GB18030。策略：

```
先按 UTF-8（fatal: true）解码 → 抛错则回退 GB18030
```

必须用 `fatal: true`，否则静默产生的 U+FFFD 替换字符会让探测失效。`gb18030` 为 GBK 超集，统一用它。

### 5.3 分页 vs 滚动：选滚动

真实分页（CSS 多栏 + 跨栏元素 + resize 重排 + 位置映射）单项成本可达两天，且未做完时体验劣于滚动。MVP 用滚动，章节为最小滚动单元。

### 5.4 存储：IndexedDB

书本原文以 `ArrayBuffer`/`String` 存入 IndexedDB，书架元数据从同一 store 反查，不引入状态管理库。

## 6. 核心流程

```
选择文件
  → 读取 ArrayBuffer
  → 编码探测（UTF-8 / GB18030）
  → 文本归一化
  → 章节切分
  → 写入 IndexedDB（books store）
  → 进入书架
  → 打开某书 → 渲染当前章 → 恢复进度
  → 滚动/切章 → 节流写回进度
```

**失败路径**：

| 情况 | 表现 |
|---|---|
| 编码两种都失败 | 提示"无法识别编码"，引导另存为 UTF-8 |
| 文件过大（> 50MB） | 拒绝导入并提示上限 |
| 空文件 / 无有效文本 | 书架插入并标记为"内容为空" |
| IndexedDB 不可用 | 降级为内存模式，显式提示刷新即丢失 |

## 7. 数据模型

```js
// IndexedDB: db = "txt-reader", version = 1

// store: "books"  (keyPath: "id")
{
  id: "uuid",
  title: "斗破苍穹",              // 文件名去扩展名，可手改
  charCount: 8123456,            // 字符数
  byteSize: 20971520,            // 原始字节数
  encoding: "gb18030",           // 探测结果
  addedAt: 1761328800000,
  lastReadAt: 1761415200000,
  text: "……",                    // 归一化后的全文
  chapters: [                     // 切分结果
    { index: 0, title: "第一章 陨落的天才", offset: 0, length: 3120 }
  ]
}

// store: "progress"  (keyPath: "bookId")
{
  bookId: "uuid",
  chapterIndex: 29,
  chapterPercent: 0.47,          // 0..1
  updatedAt: 1761415200000
}

// store: "settings"  (keyPath: "key")
{ key: "fontSize",   value: 18 }
{ key: "lineHeight", value: 1.8 }
{ key: "theme",      value: "sepia" }
```

**说明**：`chapters` 只存 `offset/length` 而非文本副本，与 `text` 共用一份字符串，避免翻倍占内存。

## 8. 技术方案

| 层 | 选型 | 理由 |
|---|---|---|
| 构建 | 无（原生 ES modules） | 零依赖、改一行刷新即见 |
| 框架 | 无（原生 DOM） | 单页复杂度不足以支撑框架成本 |
| 样式 | 原生 CSS + CSS 变量 | 主题切换只需换变量 |
| 存储 | IndexedDB（手写封装） | 无第三方依赖 |
| 编码 | `TextDecoder` | 浏览器原生支持 `gb18030` |
| 测试 | `node --test` | 内置，零依赖 |

### 8.1 目录结构

```
/
├─ index.html
├─ styles/
│  ├─ app.css
│  └─ themes.css
├─ src/
│  ├─ main.js          # 启动与路由
│  ├─ decode.js        # 编码探测        ← 纯函数，可测
│  ├─ normalize.js     # 文本归一化      ← 纯函数，可测
│  ├─ chapters.js      # 章节切分        ← 纯函数，可测
│  ├─ store.js         # IndexedDB 封装
│  ├─ bookshelf.js     # 书架
│  ├─ reader.js        # 阅读器渲染
│  ├─ settings.js      # 阅读设置
│  └─ ui.js            # 通用 DOM 工具
├─ test/
│  ├─ decode.test.js
│  ├─ normalize.test.js
│  └─ chapters.test.js
└─ docs/
   └─ product-design.md
```

**可测性边界**：`decode` / `normalize` / `chapters` 三个模块不碰 DOM、不碰存储，全部由 `node --test` 覆盖。DOM 与 IndexedDB 部分靠手动验收。

## 10. 验收标准

MVP 完成的判定：

> 从磁盘选一本 **20MB、GB18030 编码**的中文 txt：
> 1. 中文正确显示，无乱码
> 2. 章节列表数量正确，点击可跳转
> 3. 读到第 30 章后关闭浏览器
> 4. 调整字号至最大
> 5. 重新打开该书
>
> **结果：精确回到第 30 章的原阅读位置，进度百分比误差 < 1%**

附加检查：

- 20MB 文件导入耗时 < 3 秒
- 单章渲染耗时 < 100ms，滚动无明显掉帧
- 亮/暗/护眼三主题切换即时生效，无闪烁
- 删除书本后，其进度记录同步清除

## 11. 风险与待定

| 风险 | 影响 | 应对 |
|---|---|---|
| 章节正则漏识别（标题格式罕见） | 章节列表为空 | 兜底：按 8000 字固定切块 |
| 分段策略误判（每行一段 vs 空行分段） | 排版难看 | 用空行密度阈值判断，暴露为可切换设置项（v0.2） |
| 超大文件（> 50MB）内存压力 | 标签页崩溃 | 硬性上限 + 明确提示 |
| 浏览器差异（Safari IndexedDB） | 存储失败 | 降级内存模式 + 提示 |

**待定项**：

- 书名是否允许手动重命名（v0.1 暂定：允许，低成本）
- 字体是否用系统衬线字体栈（v0.1 暂定：是，`Songti SC / SimSun / serif`）
